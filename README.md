# cabxp64_installer

Программа установки и сборщик дистрибутивов для неё.
Файлы устанавливаемой программы хранятся в CAB-архивах.

- `setup.exe` — программа установки: синий экран 80x25, растровый шрифт, серая
  строка состояния с подсказками клавиш, жёлтый индикатор копирования и красный
  индикатор обратного отсчёта. Та же программа, скопированная в директорию
  установки как `uninst.exe`, выполняет удаление.
- `xpsbuild.exe` — сборщик на Turbo Vision: редактор проекта установки и сборка
  дистрибутива (CAB-архивы, описание `setup.sif`, программа установки). Для CI
  есть режим без интерфейса.

## Возможности

Программа установки:

- экраны оригинала: проверка оборудования, загрузка файлов, приветствие
  (`ВВОД=Продолжить  F3=Выход`), лицензионное соглашение
  (`F8=Принимаю  ESC=Не принимаю  PAGE DOWN=Следующая страница`), выбор директории
  установки с полем ввода и сведениями о месте на диске, копирование файлов,
  настройка, завершение с обратным отсчётом, подтверждение выхода по F3;
- обнаружение установленной версии: обновление, переустановка той же версии или
  отказ при более новой установленной версии;
- распаковка CAB-архивов с реальными именами файлов в строке состояния
  (`│Копирование: locale.nls`) и общим процентом по всем архивам;
- установка в несколько директорий (по компоненту на CAB-архив), значения реестра,
  ярлыки на рабочем столе, в меню «Пуск» и в автозагрузке, завершение процессов
  перед установкой и удалением, запуск программ после установки;
- запись в «Программах и компонентах» и журнал установки `uninstall.sif`, по
  которому удаляются файлы, ярлыки, значения и созданные разделы реестра, созданные
  директории (только пустые);
- при ошибке копирования — повтор (ВВОД) или выход (F3) с удалением скопированного;
- установка для текущего пользователя (без прав администратора) или для всех
  пользователей (права запрашиваются при запуске);
- свои иконки у установщика и у программы удаления (по умолчанию — коробка с диском
  и она же с красным крестом), иконки задаются в проекте;
- выделение текста мышью на экранах, где программа ждёт нажатия клавиши.

Сборщик:

- редактирование всех разделов проекта в диалогах, сводка проекта
  в главном окне;
- проверка масок компонента (список попадающих в CAB файлов);
- сборка дистрибутива в одном из видов: директория, один файл или оба;
- запуск собранной программы установки в отдельном окне (Ctrl+F9).

## Требования

- Windows 10 или новее.
- Visual Studio 2022 (компилятор MSVC) и Windows SDK.
- CMake 3.16 или новее.
- Git (Turbo Vision подключён субмодулем).

## Сборка

Клонировать проект необходимо вместе с субмодулем `tvision`:

```bash
git clone --recursive <адрес репозитория>
```

Если репозиторий уже склонирован без субмодуля:

```bash
git submodule update --init
```

Сборка:

```bash
cmake -S . -B build -G "Visual Studio 17 2022" -A x64
```

```bash
cmake --build build --config Release
```

Программа установки (`build\Release\setup.exe`) встраивается в сборщик ресурсом, отдельно её
распространять не нужно. Также собираются тесты: `unittests.exe` (модульные и
интеграционные) и `tuitest.exe` (проверка интерфейса), см.
[tests/README.md](tests/README.md). Программы собираются со статической
библиотекой времени выполнения и не требуют VC++ Redistributable.

Запуск тестов:

```bash
ctest --test-dir build -C Release --output-on-failure
```

Субмодуль закреплён на той же версии Turbo Vision, что и в Cabine: обходы ошибок
библиотеки (см. ниже) проверены с ней.

## Запуск сборщика

| Команда | Действие |
|---|---|
| `xpsbuild.exe` | Редактор с последним открытым проектом |
| `xpsbuild.exe проект.xsp` | Редактор с указанным проектом |
| `xpsbuild.exe --build проект.xsp` | Сборка без интерфейса |
| `xpsbuild.exe --help` | Справка по параметрам |

Параметры сборки без интерфейса:

| Параметр | Назначение |
|---|---|
| `--mode folder\|single\|both` | Вид дистрибутива (по умолчанию из проекта) |
| `--out <директория>` | Директория результата |
| `--version <версия>` | Версия продукта: от одного до четырёх чисел через точку; допускается тег вида `v1.2.3` |
| `--define <имя>=<значение>` | Переменная окружения для путей проекта; можно повторять |
| `--stub <setup.exe>` | Другая программа установки вместо встроенной |

В путях проекта (`Source`, `License`, `Output`) при сборке подставляются
переменные окружения: `Source = %APP_BUILD%\bin`. Незаданная переменная —
ошибка сборки.

Пример для CI:

```bash
xpsbuild.exe --build net8project.xsp --version 9.5.123.26 --mode both --define APP_BUILD=D:\build\Release
```

Коды завершения: 0 — дистрибутив собран, 1 — ошибка сборки, 2 — неверные параметры.

Клавиши редактора: F2 — сохранить, F3 — открыть, F4 — продукт, F5 — компоненты,
F6 — файлы дистрибутива, F9 — собрать, Ctrl+F9 — запустить установку, Alt+X — выход.
В списках: Ins — добавить, Enter — изменить, Del — удалить.

## GitHub Actions

Репозиторий является action: установщик для релиза другого репозитория собирается
одним шагом. Action работает на Windows-раннерах, скачивает `xpsbuild.exe` из
релиза XPSetup, собирает дистрибутив по проекту `.xsp` и при необходимости
прикладывает установщик к релизу.

Пример: установщик собирается при публикации релиза и прикладывается к нему.

```yaml
name: Установщик

on:
  release:
    types: [published]

jobs:
  installer:
    runs-on: windows-latest
    permissions:
      contents: write
    steps:
      - uses: actions/checkout@v4

      # Сборка программы, результат — в build\Release
      - run: dotnet publish -c Release -o build\Release

      - uses: roosslan/cabxp64_installer@v1
        with:
          project: installer/app.xsp
          version: ${{ github.event.release.tag_name }}
          mode: both
          defines: |
            APP_BUILD=${{ github.workspace }}\build\Release
          release: ${{ github.event.release.tag_name }}
```

Проект `installer/app.xsp` хранится в репозитории программы и создаётся в
редакторе `xpsbuild.exe`; путь к собранным файлам в нём задаётся переменной:
`Source = %APP_BUILD%`.

Входы:

| Вход | Назначение |
|---|---|
| `project` | Путь к проекту `.xsp` (обязательный) |
| `version` | Версия продукта или тег (`v1.2.3`); по умолчанию — из проекта |
| `mode` | `folder`, `single` или `both`; по умолчанию — из проекта |
| `out` | Директория результата, по умолчанию `xpsetup-dist` |
| `defines` | Переменные для путей проекта, по одной в строке: `ИМЯ=значение` (строки с `#` пропускаются) |
| `release` | Тег релиза текущего репозитория, к которому приложить установщик |
| `token` | Токен для загрузки в релиз, по умолчанию `github.token` (нужно `permissions: contents: write`) |
| `xpsetup-version` | Релиз XPSetup, из которого взять `xpsbuild.exe` |
| `xpsbuild` | Путь к готовому `xpsbuild.exe` (без загрузки) |

Выходы: `single` — однофайловый установщик, `setup` и `dir` — дистрибутив-директория,
`zip` — её ZIP-архив (`setup.exe`, `setup.sif`, `license.txt`, `*.cab`), `version` —
версия продукта. В релиз прикладываются однофайловый установщик и ZIP-архив.

Выбор `xpsbuild.exe`: при подключении по полному тегу (`@v1.2.3`) берётся этот
релиз, по основному (`@v1`) — последний релиз `v1.x`, иначе — последний релиз.
Если релизов нет, `xpsbuild.exe` собирается из исходников той же версии action
(несколько минут).

Ошибки сборки выводятся аннотациями GitHub. Без action сборщик можно вызывать
напрямую: при запуске в GitHub Actions он сам записывает пути к результатам в
`GITHUB_OUTPUT` (`setup`, `dir`, `single`, `name`, `version`).

## Выпуск релиза XPSetup

Релиз выпускается тегом, совпадающим с версией в `src/common/version.h`
(`XPSETUP_VERSION`): для версии `1.0` — `v1.0` или `v1.0.N`. Workflow
`release.yml` собирает и проверяет проект, публикует релиз с `xpsbuild.exe`,
`setup.exe` и `SHA256SUMS.txt` и переносит основной тег (`v1`) на новый релиз.

```bash
git tag v1.0.0
```

```bash
git push origin v1.0.0
```

## Дистрибутив

| Вид | Содержимое |
|---|---|
| Директория | `<Output>\setup.exe`, `setup.sif`, `license.txt`, `*.cab` |
| Один файл | `<Output>\<SingleFile>` — `setup.exe` с дописанным CAB-архивом, внутри которого `setup.sif`, `license.txt` и `*.cab` |
| Оба | директория в `<Output>\setup`, один файл в `<Output>` |

Однофайловая программа установки при запуске распаковывает данные во временную
директорию (экран «Программа установки загружает файлы») и удаляет её по
завершении. Из директории результата перед сборкой удаляются прежние `*.cab`,
`setup.exe`, `setup.sif` и `license.txt`, поэтому она не должна совпадать
с директорией проекта.

## Формат проекта

Проект (`*.xsp`) и описание установки в дистрибутиве (`setup.sif`) — текст в UTF-8
в стиле `txtsetup.sif`: секции `[Имя]`, строки `ключ = значение` и строки-списки,
поля которых разделяются запятыми. Значение с пробелами, запятыми или `;`
заключается в кавычки, `""` внутри кавычек означает одну кавычку. Строка,
начинающаяся с `;`, — комментарий. В `setup.sif` поля сборщика (источники файлов,
секция `[Build]`) не записываются.

Пример — [example/demo.xsp](example/demo.xsp), шаблон для net8project —
[example/net8project.xsp](example/net8project.xsp).

| Секция | Содержимое |
|---|---|
| `[Product]` | `Name`, `Version`, `Publisher`, `ProductCode` (GUID — ключ записи в «Программах и компонентах»), `InstallDir`, `AllowChangeDir` (0/1), `Scope` (`user`/`machine`), `License` (текстовый файл); для сборщика — `Icon` и `UninstallIcon` (файлы `.ico` для `setup.exe` и `uninst.exe`) |
| `[Directories]` | `номер = путь`; компоненты ссылаются на номер |
| `[Components]` | идентификаторы компонентов в порядке установки |
| `[Component.<id>]` | `Cabinet`, `Directory`, `Description`; для сборщика — `Source` (директория или файл относительно проекта), `Include` и `Exclude` (маски через `;`, исключения проверяются по имени и по относительному пути), `Recurse` |
| `[Shortcuts]` | `Desktop\|Programs\|Startup, имя, объект[, параметры[, рабочая директория]]`; для меню «Пуск» имя может быть `Группа\Имя` |
| `[Registry]` | `HKCU\|HKLM, раздел, параметр, REG_SZ\|REG_EXPAND_SZ\|REG_DWORD, значение` |
| `[KillProcesses]` | имена процессов, завершаемых перед установкой и удалением (только в сеансе текущего пользователя) |
| `[RunAfterInstall]` | `программа[, параметры]` — запускается после выхода из программы установки |
| `[Build]` | `Output`, `SingleFile`, `Mode` (`folder`/`single`/`both`), `Compression` (`NONE`/`MSZIP`/`LZX:15..21`) |

Переменные в путях и значениях: `%INSTALLDIR%`, `%APPDATA%`, `%LOCALAPPDATA%`,
`%PROGRAMFILES%`, `%PROGRAMFILES(X86)%`, `%PROGRAMDATA%`, `%USERPROFILE%`,
`%DOCUMENTS%`, `%DESKTOP%`, `%PROGRAMS%`, `%STARTUP%`, `%WINDIR%`, `%SYSTEM%`,
`%TEMP%`, а также любые переменные окружения. При `Scope = machine` рабочий стол,
меню «Пуск» и автозагрузка — общие для всех пользователей.

## Удаление

В «Программах и компонентах» записывается `"<директория>\uninst.exe" /uninstall`.
`uninst.exe` не может удалить сам себя, поэтому копирует себя во временную
директорию, запускает копию и завершается; копия после удаления программы удаляет
себя. Подтверждение удаления — клавиша L, как при удалении раздела в программе
установки XP. `uninst.exe`, запущенный без параметров (например, двойным щелчком в
директории программы), тоже выполняет удаление: рядом с ним лежит журнал установки,
а описания дистрибутива нет.

## Иконки

В программе установки две группы иконок: 1 — установщик, 2 — программа удаления.
Проводник показывает первую группу, поэтому при установке у `uninst.exe` группа 1
удаляется и видна иконка удаления.

Иконки по умолчанию (`src/setup/setup.ico`, `src/setup/uninst.ico`, размеры 16–256,
32 бита) рисует скрипт `tools/make_icons.py`:

```bash
python tools/make_icons.py
```

Свои иконки задаются в проекте ключами `Icon` и `UninstallIcon` (путь относительно
проекта, допускаются переменные окружения). Сборщик заменяет ими иконки в копии
`setup.exe` перед дописыванием CAB-архива; `UninstallIcon` без `Icon` и наоборот
допустимы — для незаданной остаётся иконка по умолчанию. Проводник кэширует иконки:
после замены может потребоваться обновить окно или перезапустить Проводник.

## Журнал

Программа установки и удаления ведёт журнал в `%TEMP%\XPSetup.log`: каждый запуск
дописывается с заголовком сеанса (программа, параметры, версия Windows, наличие
прав администратора), далее — режим дистрибутива, продукт, найденная прежняя
версия, выбор пользователя на экранах, завершённые процессы, распаковка каждого
файла, значения реестра, ярлыки, регистрация, ошибки и код завершения. Строки с
ошибками начинаются с `ОШИБКА:`, на экране ошибки указывается путь к журналу.
Другой файл журнала задаётся параметром `/log <файл>`:

```bash
setup.exe /log C:\Temp\install.log
```

После успешной установки записи этого сеанса копируются в `setup.log` в
директории установки; файл удаляется вместе с программой.

Сборщик пишет журнал сборок в `%APPDATA%\XPSetup\xpsbuild.log`: проект, состав и
размер каждого CAB-архива, созданные дистрибутивы и ошибки.

Коды завершения программы установки: 0 — выполнено, 1 — ошибка, 2 — отменено
пользователем.

## Особенности и ограничения

- Растровый шрифт «Terminal» содержит только символы OEM-кодировки системы:
  кириллица в нём есть при кодовой странице 866 (русская Windows). Иначе
  используется шрифт Lucida Console.
- Windows Terminal не поддерживает растровый шрифт и смену палитры: программа
  установки перезапускает себя в классическом окне консоли (`conhost.exe`).
- Лицензия отображается как обычный текст (UTF-8 или ANSI); RTF не поддерживается.
- Тексты экранов собраны константами в начале `src/setup/ui.cpp`; название
  продукта подставляется в них без склонения.
- Ограничения формата CAB: файл до 2 Гб, не более 65535 файлов в архиве. Пустые
  директории в CAB не хранятся.
- Занятый файл, который не удалось удалить, удаляется при перезагрузке, если на это
  хватает прав.
- Манифест программы установки задаёт `asInvoker`: иначе Windows запрашивает
  права администратора для любого `setup.exe`.
- Выделение текста мышью приостанавливает вывод в консоль, поэтому на время
  копирования файлов и настройки оно выключается и включается снова на экранах
  ожидания клавиши.

## Доработки Turbo Vision

Модули `src/tv` (диалоги, русские горячие клавиши, русифицированные строки) взяты из
Cabine вместе с описанными там обходами ошибок библиотеки. Дополнительно:

- **Длинные пункты флажков и переключателей.** `TCluster::drawMultiBox` не рисует
  пункт, если длина его текста в байтах плюс 5 не меньше 80: русский текст длиннее
  ~37 букв пропадает. Тексты пунктов короче этой границы, длинные пути директорий
  сокращаются.
- **Размер окна диалога** задаётся при создании: рамка окна создаётся по его
  размеру, а `setBounds` её не изменяет.
